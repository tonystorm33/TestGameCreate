# 流程实验室与代码解析

## 如何体验

打开 PlayScene，点击知识卡片，再点击“进入独立流程实验室”。也可直接打开 `Assets/Scenes/Labs` 内的场景并 Play。
实验 UI 和可视化对象在运行时创建；编辑状态下场景根节点挂载对应的 Lab 脚本。

每个场景提供单步、完整流程、重置、全部测试、真实状态日志、完整源文件和返回目录。
建议先单步观察，再运行测试，最后打开源文件对照方法。测试输出到 `Documentation/Validation/LabReports`；Windows 开发构建输出到 `Application.persistentDataPath/LabReports`。

| 场景 | 实际运行内容 | 可直接观察 |
| --- | --- | --- |
| EcsFlowDemo | Entities 1.0.16 的自有 World、EntityManager、SystemBase、查询与组件变更 | 方块位置来自组件数据；冻结标签排除更新；销毁使句柄失效 |
| NetworkSyncDemo | 本机两个 TCP 套接字、JSON 消息、权威状态、版本化快照 | 左服务端／右客户端；延迟期间状态不同；最终一致；非法请求被拒绝 |
| HotUpdateDemo | 构建清单、本机 HTTP、UnityWebRequest、真实 AssetBundle 与 Prefab | V1 小红方块到 V2 大蓝方块；404／CRC 失败时保持已提交版本 |
| ObjectPoolDemo | 内置 ObjectPool 管理真实 GameObject | 同一编号复用；速度和寿命重置；活跃上限与空闲上限各自生效 |
| LifecycleDemo | 引擎真实 Awake / OnEnable / Start / Update / OnDisable / OnDestroy | 旋转、回调计数、协程心跳与事件订阅随启用状态变化 |

资源包已由 Unity 构建并放入 `Assets/StreamingAssets/LearningLabPackages`。可用 `Tools → Unity Learning → Build Lab Content` 重新构建。
全场景自动验证菜单为 `Tools → Unity Learning → Run All Lab Scene Tests`，它会保存当前编辑修改的确认后进入 PlayMode、依次运行所有场景，最后返回目录并停止 Play。
本机 HTTP 使用随机 loopback 端口；项目 HTTP 设置为 DevelopmentOnly，实验需在编辑器或 Windows Development Build 中运行。

## 共用架构

`LearningLabBase` 只负责界面、相机、流程调度、代码展示、报告和统一退出。业务放在派生 Lab 中。

```text
OnEnable → 创建 UI / 相机 → InitializeLab
按钮 → StepLab / ResetLab / BeginTests
每帧 → TickLab → 业务模拟或消息泵
BeginTests → TestRunner → ExecuteTests → Check → 写报告
离开场景 → OnDisable → StopAllCoroutines → DisposeLab → 清理表现与字体
```

`ExecuteTests` 使用场景真实方法，检查结果而不是生成假日志。网络测试会等待真实收包；资源测试会等待真实 HTTP 下载和包加载。
测试中控制按钮禁用，避免用户操作污染断言；“返回目录”和 Esc 始终可退出。退出时停止测试与业务资源。
场景源码读取 `Resources/Learning/Labs/Source/*.cs.txt` 的镜像。修改源文件后执行 `Tools → Unity Learning → Sync Lab Source`；全场景测试会自动同步，避免展示旧代码。

## ECS：数据与系统真正分开

```text
CreateWorld
  new World → CreateSystemManaged<LabMoveSystem>
Spawn
  CreateArchetype(Position, Speed) → CreateEntity → SetComponentData
Simulate(dt)
  World.SetTime → LabMoveSystem.Update
    Query(Position RW, Speed RO, Exclude Frozen)
    position += speed × dt → SetComponentData
  SyncViews → 只读取组件，更新可视化 Transform
AddComponent<Frozen> → 查询排除
DestroyEntity → Exists=false
DisposeWorld → 系统与实体整体结束
```

| 方法 | 输入与前置条件 | 输出／副作用 | 为什么这样调用 |
| --- | --- | --- | --- |
| CreateWorld | 尚无自有 World | 创建 World 和 System | 隔离实验所有权，退出时可完整释放 |
| Spawn | World 已创建 | 组件组合与实体；表现映射 | 数据不存放在每个 MonoBehaviour.Update 中 |
| Simulate | delta >= 0，World 存在 | 推进时间、修改组件、刷新视图 | 正常运行和固定步长测试共用同一计算路径 |
| LabMoveSystem.OnUpdate | 匹配查询的实体 | 修改位置组件 | Frozen 是查询条件，不是表现对象开关 |
| SyncViews | 存活的实体句柄 | 数据映射至 GameObject | 这是显式表现桥，不是 Entities Graphics 渲染 |
| DisposeWorld | 自有 World | 结束全部实体和系统 | 不销毁默认 World，也不影响其他场景系统 |

8 项验收：创建、积分结果、冻结不动、解冻恢复、表现一致、句柄失效、World 释放、重复初始化。
实现刻意使用临时实体数组逐行处理，便于教学；不是 Jobs／Burst 性能基准，也不是 Baking/SubScene 渲染示例。
拓展练习：在不改变测试预期的前提下，添加 ECB、批量查询或 Job 版本，然后测量与原版差异。

## 网络同步：真实字节传输与权威状态

```text
LoopbackTransport
  TcpListener.Start(127.0.0.1:0)
  TcpClient.Connect → AcceptTcpClient → 后台 ReadLine
SendCommand → JSON + 换行 → NetworkStream.Write
后台收包 → ConcurrentQueue（无 Unity 对象访问）
主线程 Pump
  检查操作白名单 + 单调请求序号
  修改 Server 状态 / version
  QueueSnapshot（应用层延迟）→ 服务端 NetworkStream.Write
客户端读队列 → ApplySnapshot → 只接受更新的 version → 刷新颜色
Dispose → 关闭连接 / listener / 后台读线程
```

TCP 是字节流，换行承担消息边界；生产协议还应实现受限长度帧、序列化规范、连接认证、按玩家限频和异常隔离。
测试只开放本机 loopback，不连接外部服务。它验证同进程的实际两个端点，不宣称完成跨机器或 NGO 的部署验证。
“拒绝非法操作”针对消息类型与重放序号，不等于生产身份认证。
应用层版本仍有教学价值：避免旧快照覆盖新显示；这与 TCP 传输本身是否有序是两个层次。

10 项验收：连接、初始快照、切换往返、非法操作、重放请求、旧快照、延迟窗口、最终一致、连接释放、重连快照。
重连会重置客户端显示版本，然后等待服务端当前快照，不能复用原客户端的版本号冒充已经同步成功。
拓展练习：增加第二客户端、每客户端序号与权限校验；再用 NGO 的 RPC / NetworkVariable 实现同一个业务，并保持状态验收相同。

## 热更新：真实包、真实下载、延后提交

```text
LabContentBuilder.Build（编辑器）
  创建 V1 / V2 Prefab + 材质
  BuildPipeline.BuildAssetBundles
  读取 hash / CRC → 写 manifest.json
ReadManifest → 校验平台与版本
PrepareServer → 静态路由 /v1 /v2 → 本机 HTTP
ApplyVersion
  检查版本 / 防并发 → 等待缓存
  GetAssetBundle(url, hash, crc) → SendWebRequest
  成功 → GetContent → LoadAssetAsync
  可用 Prefab → Instantiate 新对象
  提交 currentView / currentBundle / AppliedVersion
  清理旧对象与旧包
失败 → 不提交 → 保留旧版本
CancelTransaction → Abort / Dispose / StopCoroutine / 卸载暂存包
DisposeLab → 停止 HTTP、清理当前实例和资源包
```

| 阶段 | 失败处理 | 测试如何验证 |
| --- | --- | --- |
| 清单缺失 | 提示重新构建，不启动下载 | ReadManifest 返回失败 |
| HTTP 404 | 释放请求，不变更版本 | 比较当前实例引用、AppliedVersion 和失败计数 |
| CRC 错误 | 下载校验失败，不提交 | 使用独立故障缓存键，避免有效缓存绕过故障注入 |
| 资源不存在 | 卸载暂存包 | 加载到有效 Prefab 之前不销毁旧实例 |
| 取消事务 | 取消请求与临时包 | pending / staging / Busy 归零，已提交版本保留 |
| 退出 | 清理当前包和服务 | 重新进入后可以再次执行 V1 完整流程 |

10 项验收：清单、HTTP 启动、V1 全流程、重复版本、V2 替换、404、CRC、取消、退出、重新运行。
示例包各自包含资源且不共享依赖，因此旧包可在旧实例失活后 Unload(true)。生产项目的共享依赖需要引用计数和完整依赖图。
示例未实现数字签名、多包磁盘事务、客户端兼容升级、断点续传与代码热更新；CRC 仅验证内容损坏，不能提供来源认证。
拓展练习：把本机服务换成测试 HTTPS；加入已提交清单落盘、重启恢复、多包依赖和回滚策略。

## 对象池：真实对象身份与容量

```text
CreatePool → 指定 create / get / release / destroy 回调
Rent → 业务活跃上限检查 → Get → 重置位置、旋转、速度和寿命
Simulate → 更新实际 Transform → 寿命结束时 Return
Return → 活跃集合检查 → Release → 关闭对象
空闲数量超过 2 → destroy 回调
DisposeLab → 回收活跃对象 → Clear 空闲对象
```

11 项验收覆盖 defaultCapacity、创建、运动、回收、引用身份复用、复用重置、重复回收、活跃上限、空闲上限、清理和再次运行。
活跃上限为业务规则 4，maxSize=2 只限制保留的空闲对象；二者不能混用。
本实验统一由 Lab 推进运动，不是 Rigidbody 物理发射器；原课程另提供 Rigidbody 子弹示例。

## 生命周期：回调来自引擎

```text
CreateActor（不活跃）→ AddComponent / 配置 Report
SetActive(true) → Awake / OnEnable
下一引擎帧 → Start / Update
Pulse.Invoke → 已订阅的 Receive
actor.enabled=false → OnDisable → 解绑 / StopCoroutine
actor.enabled=true → OnEnable（Awake / Start 不再重复）
Destroy → OnDisable / OnDestroy
```

10 项验收覆盖延迟初始化、首次回调、Update、订阅、禁用与协程停止、解绑、再次启用、重复监听、销毁和新实例。
该场景演示核心活跃周期，不涵盖完整 PlayerLoop、物理更新和跨对象初始化顺序；课程正文继续解释这些内容。

## 增加一个实验

继承 LearningLabBase；定义 LabId、标题、指南、Phases 和 SourceFiles；实现 InitializeLab、StepLab、ResetLab、TickLab、ExecuteTests、DisposeLab。
创建独立场景挂脚本，加入 Build Settings，将 KnowledgeTopic.demonstrationScene 指向场景名。
测试至少覆盖成功路径、一次失败、重置、再次运行与退出释放。新的知识点以同样方式接入，主目录无需知道具体实验实现。
